# FRD deviations

Deliberate departures from `docs/FRs/FUNCTIONAL REQUIREMENTS.md`, each approved by the owner and recorded here with
its reason, scope and how to undo it.

| FR | Deviation | Scope | Reason | Undo |
|---|---|---|---|---|
| FR-TM-001 (Clarity Index) | A deadline with a real date but no time is **created**, due at the end of that day (stored date-only, shown as 11:59 PM), with the reply line "11:59 PM assumed. Say 'change time' to set another." The Clarity Index would ask for the time first. A deadline with **no date still asks**. | Only with `CHAT_FIXES_V2=on` (default off). Approved 2 Nov 2026. | Asking the time for every dated deadline ("submit the invoice on the 9th") cost a turn for little gain; a date-only deadline keeps useful reminders (the day before at 10 AM and the morning of the day; no late-night "1 hour left"). "change time" (or "change time to 5 pm") sets it afterwards. | `CHAT_FIXES_V2=off` |
| §1.2 "Third-party calendar integration (Phase 2)" | Built now, on the phone's own calendar (`expo-calendar`) instead of a third-party API: write into the Google calendar of the signed-up account (two-way for the app's own task events since PR B, 12 Nov 2026: time, title, ✓, delete come back on app open / foreground / every 15 min; routine events stay one-way; other calendars are never imported) when it's on the phone (Android can't create a calendar inside a Google account; events then sync to Google; only the app's marked events are touched; changed 11 Nov 2026), else a separate "Life Organizer" calendar; busy time read on the phone. No Google OAuth, no `.ics` feed. See [calendar.md](calendar.md). | Only with `CALENDAR_SYNC=on` (default off) and the user's switch in Settings. Approved 3 Nov 2026. | The owner asked for calendar integration before the 10 Nov freeze; the device route needs no keys, no accounts and no cost, and keeps calendar contents on the phone. | `CALENDAR_SYNC=off` (events already written stay until "Remove all") |
| Non-functional: secure transport (HTTPS) between app and API | The demo **release** APK allows plain HTTP (`android:usesCleartextTraffic="true"`, local config plugin `mobile/plugins/withCleartextTraffic.js`), so it can reach the backend on the laptop at `http://<laptop-ip>:5050` over a hotspot / LAN. The API address can be set on the phone (Settings → long-press the version → Server address, checked against `/health` before saving); USB with `adb reverse tcp:5050 tcp:5050` and `127.0.0.1` is the fallback. | Demo build only, app-wide (Android can't limit cleartext to private IP ranges). Approved 12 Nov 2026. | The backend runs on the student's laptop with no domain or certificate; a TLS setup (tunnel or reverse proxy with a certificate) costs time and money before the evaluation. Firebase sign-in and other third-party calls stay on HTTPS. | Remove the plugin from `app.json` and put the API behind HTTPS (e.g. a reverse proxy with a certificate) |
